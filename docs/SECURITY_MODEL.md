# Модель безопасности / Security model

Краткое описание того, как генератор создаёт пароли и почему он устойчив.

## Источник случайности

Всё случайное берётся из `secrets`, а `secrets` обращается к
`getrandom(2)` / `CryptGenRandom` — криптографическому генератору
операционной системы:

* Linux: `getrandom()` из ядра (CSPRNG), засеянный аппаратнымentropy;
* Windows: `BCryptGenRandom` / `CryptGenRandom`;
* генератор `random` из стандартной библиотеки **не используется нигде**.

Алгоритм (см. `pastypw/core/generator.py`):

1. из каждого включённого набора символов берётся по одному символу —
   это гарантирует, что в пароле будут цифра, заглавная, строчная и спецсимвол;
2. остальные позиции добираются из общего алфавита;
3. позиции перемешиваются алгоритмом Фишера–Йетса с `secrets.randbelow()`,
   чтобы порядок классов не выдавал шаблон.

Сбой при пустом наборе символов обрабатывается: кнопка «Сгенерировать»
блокируется и показывается подсказка.

## Оценка стойкости

```
энтропия = длина × log2(размер алфавита)
```

Предполагается равномерное распределение (это верно для CSPRNG).
Время взлома считается для 10<sup>10</sup> вариантов в секунду — типичный
бюджет офлайн-перебора на GPU.

## Что программа НЕ делает

* не открывает сетевых соединений (нет `requests`, `urllib`, сокетов);
* не отправляет телеметрию и не проверяет обновления;
* не пишет пароли в системный лог;
* не хранит мастер-пароль и не шифрует файл (см. `SECURITY.md`).
